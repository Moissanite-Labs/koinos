# Open collaboration reference: implementation coordination

This extends the 0.1 reference; keep that format and its tests compatible. The founder now requests permissionless collaboration, complete recorded contribution credit, tokenized ownership, configurable dilution, and a hybrid revenue model rewarding both common infrastructure and specialized marketplaces. The one-percent-per-contributor note is an economic scenario to implement and analyze, not a universal promise of fairness.

## Product and trust model

Anyone can publish a profile, opportunity, project, contribution claim, or review without a membership list. Concurrent signed work merges by content identity into a directed acyclic graph (DAG), not by a steward's single sequence. Preserve conflicting judgments, unaccepted work and attribution. A signed claim is not automatically earned credit.

The prototype has an independently runnable local EVM implementation. Ownership and revenue contracts enforce explicit pre-agreed rules; no live chain or funds. Objective verification can avoid discretionary approval. Reviewer/model quorum is a separately labelled trust model. A model verdict is evidence, not hidden permission to move assets. Tokens enforce on-chain balances and entitlements only; legal equity requires an actual agreement and legal structure.

## Open protocol agent ownership

Own `src/open-protocol.mjs`, `src/open-demo.mjs`, `test/open-protocol.test.mjs`, `docs/open-protocol.md`, `examples/open-collaboration.json`. Use Node built-ins and existing core signing/canonical helpers, no runtime dependency. Agree a stable API with UI agent immediately.

API: `createOpenRecord({records,identity,kind,body,parents?,time?})`, `verifyOpenBundle(bundle)` -> projection, `mergeOpenBundles(...bundles)` -> canonical bundle, `createOpenBundle(records)`, `createOpenDemo()` -> public bundle only. Bundle format `koinos-open/0.2`; each Ed25519-signed record has protocol, actor, kind, body, time, parents (sorted unique preceding hashes), id, signature. Signature domain `koinos-open/0.2\n` plus SHA256 id. IDs hash canonical unsigned fields. No central sequence, all references resolve in the graph, deterministic topological sort; reject cycles, missing parents, duplicates with altered content, foreign references, malformed/oversized data. Preserve unsupported versions as errors, not inferred authority.

Kinds at least: self-signed profile (name, skills, needs, role, statement); opportunity (title, problem, seeks, offers, criteria, terms digest/reference); project genesis (title, opportunity reference, immutable policy description/terms digest, originator reference); contribution (project, title, evidence URI/digest, references to prior contributions, proposed credit split); review (exact contribution, criteria digest, decision, rationale, reviewer type human/model and model/version metadata when applicable); dispute (contribution/review reference and reason); feedback consent (actor's own contribution, allowed purposes such as evaluation/training, grant or revoke); settlement reference (exact contribution id plus chain id, contract and tx hash, explicitly unverified until checked against chain).

Validate actor ownership for profile and feedback consent; references must actually exist and concern the same project. No policy owner can erase someone else's claim/review. Reviews by contributor are recorded as self reviews, never labelled independent. Conflicting reviews and disputes remain visible. Do not turn favorable review count into automatic accepted credit. Derive credits proposed/attested/disputed/settlement-reference only with truthful labels.

Provide `matchOpportunities(bundle, profileId)` deterministic explainable skills/needs overlap, no identity ranking. Provide `exportConsentedFeedback(bundle, purpose)` with explicit current contributor opt-in, minimal metadata, no private URLs or free-form work/terms bodies by default. Consent revocation removes future export, does not claim recall of past exports. Source and branch project credits stay distinct. The same person may earn both. A key is not proof of unique personhood; do not award value merely for registering a key.

## Contract agent ownership

Own `contracts/` including isolated pinned dev tooling/package-lock, Solidity contracts, tests, local EVM demo, and `docs/economics/contracts.md`. Dependencies must stay inside contracts/node_modules; no install in existing root. Node22 available, no forge/anvil installed. Use exact OpenZeppelin, solc, ethers versions and an isolated in-process EVM test harness. Verify current docs as needed. No live deployments, keys, accounts, payments, or secrets. Solidity SPDX UNLICENSED for our code, preserve dependency licenses.

Implement an ERC20 project ownership token with immutable terms, acceptance policy and bounded minting. Initial supply must be positive and openly allocated. A valid contribution can automatically mint a configurable fraction of post-mint supply (one percent example: ceil(S*100/(10000-100))). Bound rate, maximum supply, award count and amounts. Show rounding explicitly; do not describe whole-token approximation as exact percentage. All existing balances dilute, credit history does not disappear. No administrator mint, confiscation, rewrite, pause or upgrade shortcut. Policy changes require a new opted-into project instance for this prototype.

Anyone can submit a claim and commit/reveal its proof; no contributor allowlist. The immutable verifier determines admissibility. Include a real on-chain objective predicate example (clearly an educational hash-preimage task, not proof of software quality) and an immutable EIP712 reviewer-quorum verifier. Quorum attestations bind chain, project contract, actor/principal, exact evidence, unique work nullifier, terms/criteria, credit plan and reward policy; reject duplicate/unknown signers, replay, malformed signatures, wrong domain. Objective predicate must bind its unique work item and prevent repeated awards. Do not permit caller-chosen nullifiers to reward the same proof repeatedly. Reviewer quorum is trusted, never labelled fully trustless. Document Sybil, collusion, censorship and external-verifier limits.

Commit/reveal binds claimant, actor, evidence, nullifier, credit plan, proof hash and salt; reveal after a prior block, exactly once, front-run copying cannot redirect rewards. Agent delegation is principal-created, task/project-specific, expires, revocable, and bound to the exact credit-plan hash; it only submits/claims, never grants ownership spending. Preserve actor and principal in events.

Credit plans contain bounded, unique sorted recipient addresses and integer basis-point weights summing to10000. Distribute minted integer units deterministically with no lost units; use explicit remainder rule. Track immutable cumulative earned credit separately from transferable ERC20 balances. Preserve submitted/accepted event references to the off-chain evidence digest. Contracts cannot infer omitted contributors or detect plagiarism without a verifier.

Implement revenue sharing for a pinned ERC20 payment asset. Source/common infrastructure has its own project token; specialized branches have separate project tokens and an immutable disclosed revenue fee to the common source project. Branch revenue splits between its holders and source holders. Anyone may deposit funded revenue; holders withdraw only their accrued balance. Transfers and later mints must not transfer or retroactively claim already-accrued revenue. Prefer per-share accrual with corrections/debt settled on every token update; explicit amount/supply bounds prevent overflow. Preserve fractions/rounding honestly; account for source fee, payouts and retained rounding. Reject fee-on-transfer assets or account explicitly. Checks/effects/interactions, non-reentrant payouts, SafeERC20, solvency, no unbounded loops over all holders. Token ownership does not make an ERC20 asset safe.

Provide a permissionless project factory or equivalent creation path, a runnable local deployment/exercise demo producing a PUBLIC receipt report (no keys), and tests for proof rejection, replay, copied proof, split conservation, dilution, caps, principal/agent scope+revocation, accrued revenue before/after mint/transfer, source/branch split, withdrawals and reentrancy. Expose report generation API to UI agent or a committed fixture labelled local test evidence. Report fields must distinguish actual locally executed transactions from projections. Real x402 transport is not required unless demonstrable; document clean adapter boundary and stable receipt fields instead of pretending integration.

## Workbench agent ownership

Own `web/` new open.html/open.mjs/open.css and necessary `src/server.mjs` routes plus `test/open-server.test.mjs`. Preserve existing workbench and route `/open` to a new coherent product experience. Coordinate open protocol API. Build opportunity discovery/matching, project formation/story, contribution graph/credit register including conflicting judgments, source-versus-branch ownership, and editable economic simulator (one-percent dilution scenario, split of revenue to source/branch, cap table). Clear distinction between proposed credit, immutable earned credit and transferable ownership. Show explicit agreed policy and who/what can decide. Explainable matches, not invented users or real economic performance.

Use deterministic pure browser arithmetic with BigInt or exact decimal parsing for economic projections; avoid floating point for actual balances. Simulations must be labelled. Provide import/export open bundles, independently verify Ed25519 signatures in browser (can extend verifier dispatch with a separate open function), server semantic verification and merge with visible result. Browser actions must not overwrite a rejected import or imply on-chain execution. Include optional local-EVM report viewing labelled locally executed fixture, not live balance. User-facing flows should show why a claim can earn shares and where judgment remains.

Use the previous warm editorial design but favor functional workspace over landing-page hero. Ensure keyboard/mobile usability and hostile input rendering safety. Tests and actual browser QA at desktop/mobile. No public deployment.
